# Reporting evaluator vulnerabilities

Please send sensitive evaluator or evidence-integrity reports privately to info@paloframework.org. Avoid public issue attachments containing credentials, private documents or exploitable unreleased submissions. Include the affected commit, minimal synthetic reproduction and expected versus observed behaviour. Do not send real company records.

There is no dedicated security team, guaranteed response time or independent appeal arbiter currently appointed. GitHub private vulnerability reporting has not been verified as enabled. The maintainer handles this mailbox; it is not an independent review channel.

Evaluator 0.2 has a known non-claim exclusion vulnerability. Its acceptance output must not be used to qualify submissions. The 0.3 draft repair requires review. See `docs/audit-response-2026-11-11.md` and `docs/evaluator-0.3-draft.md`.
